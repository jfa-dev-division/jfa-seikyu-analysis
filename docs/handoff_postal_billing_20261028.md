# 別Mac向け引き継ぎ：2027年分の郵送請求書と紹介割引

更新日：2026年10月28日。今回の再開時は本書を最初に読む。

## 1. 現在の目的

既に手動運用している紹介制度について、会員の `次年度紹介割引` の金額を2027年分の郵送請求書本文に表示し、郵送発行を早急に進める。

紹介制度全体、12人上限、13人目以降、辞退・期間・繰越の再設計は今回は対象外。以前挙げた未決事項をすべて解決しないと郵送発行できない、という進め方はしない。

## 3. 実施済み／未実施

- 実施済み：10月28日DDRの解析、最小修正案の作成、今回の引き継ぎ文書とスクリプトテキストの保存。
- 未実施：FileMaker本体への修正反映、Org_Messageの2027年郵送文面の編集、請求パターン更新、請求書作成、印刷、メール送信。
- スクリプトテキストは修正後の提案。FileMakerへ反映済みのエクスポートではない。
- ユーザーから、文書作成完了後にGitHubと同期する指示を受けている。同期の成否・コミットはGit履歴と最終報告で確認する。本書が存在するだけでpush済みと判断しない。

## 4. 最新DDRの重要な差分

`次年度紹介割引` は既に追加済みで、計算は `次年度基本年会費 / 12 * 紹介者数_会員毎`。

`次年度請求分_New` は `次年度基本年会費 - 次年度入金計 - 次年度紹介割引`。10月14日の資料にある「紹介割引未接続」は現在は該当しない。

`新請求パターン更新` は減額後の次年度請求分_Newを請求パターンの年会費額に渡す。したがって今回追加するのは割引の表示であり、請求額からもう一度引く計算ではない。

## 5. 最小修正の実施箇所

| 対象 | 変更 |
| --- | --- |
| 対象請求書作成2026（ID 248） | ループ内のJSONに `紹介割引額` を追加し、会員の次年度紹介割引をJSONNumberで渡す |
| 請求書作成2026（ID 251） | `$date`取得直後で `$紹介割引額` を受け取る |
| 同じ子スクリプト | 既存の置換処理の末尾で `{{紹介割引明細}}` を割引説明文に置き換える |
| Org_Messageの2027年・郵送・請求レコード | メッセージ本文の `###` の下などへ `{{紹介割引明細}}` を追加し、来年用に文面を編集する |

表示案は「※上記の請求額には、紹介者割引500円を適用済みです。」。割引0円なら空文字にする。金額は既存のフィールド値をそのまま使う。

新しいフィールド・TOは不要。郵送本文に生成済みの文章が保存され、「請求書印刷A4」がそれを印刷する。レイアウトは項目追加ではなく、文章の収まりを確認する。

## 6. 別Macでの作業手順

1. GitHubの最新版を取得し、本書・やり取り記録・スクリプトテキストを読む。
2. 実際のFileMakerの親・子スクリプトをDDRと比較する。10月28日以降に変わっていれば、古い全文で上書きせず、3か所の差分を現行版へ反映する。
3. 親のJSON追加と子の2ステップ追加を反映する。テキストはFileMakerスクリプトワークスペースで設定するための参照用で、単純なテキスト貼付だけでスクリプト全体をインポートできる形式ではない。
4. `Org_Message` の年度＝2027、請求手段＝郵送、請求＝請求の文面を用意し、差込記号を追加する。本文の実データはDDRでは確認できていないため、既存文面を読みながら修正する。
5. 会員側で `gNYear＝2027` と今回の郵送対象を確認する。口座振替会員は通常請求の対象外。
6. 対象会員の「新請求パターン更新」または「新請求パターン全更新」を実行し、請求コードが割引後の金額を参照することを確認する。
7. 郵送・割引ありと郵送・割引なしの各1件で、請求額、生成本文、印刷プレビューを確認する。
8. 問題がなければ郵送対象に対して一括生成し、既存の印刷手順で発行する。「請求書出力2024」など旧スクリプトが2026版の請求書にそのまま適合するとは確認していないので、名称だけで実行しない。

## 7. 発行時に必要な確認だけ残す

- **メール実送信**：子はメール・口座振替Mなら送信する。今回の試行・一括生成の対象に混ぜない。
- **同日重複**：会員番号＋発行日が同じ既存請求書はスキップされる。作成済み本文は再実行だけでは変わらない。必要なら既存の郵送請求書だけを対象に本文更新する別処理を検討する。発行日を偽って回避しない。
- **金額と説明**：差込文が出ても、請求コードが古いままなら請求額は更新されない。請求パターン更新後の金額と一致させる。
- **本人分0円**：既存の請求パターン生成は本人分0円で終了する。今回の実対象に該当者がいれば個別確認する。制度全体の修正を今回の前提にはしない。
- **固定費の年度参照**：以前指摘した不整合は最新DDRにも残る。今回の実対象で金額差が生じる場合は、その箇所を個別に確認する。
- **決済URL・QR**：新しい請求パターンで空欄になっていないか、文面・帳票で使う場合に確認する。
- **保存済み本文**：文面テンプレートの変更だけでは作成済み請求書へ遡及しない。
