3. 年会費の業務仕様

3.1 対象年度と基本料金

  • 年会費の対象期間は、毎年1月1日から12月31日まで。
  • 10月頃に次年度の請求を準備する。振込・口座振替のどちらの会員も、次年度の負担額の算出が必要。
  • 正会員本人の年会費は、次年度1月1日時点で22歳以下なら22歳以下の年会費、それ以外は通常の年会費を適用する。
  • 家族会員費は主会員に人数分を請求し、家族会員本人への別請求とはしない。
  • 紙媒体とPDFの両方で会報を受け取る場合は会報オプション費を加算する。
  • 海外在住で紙媒体の会報を受け取る場合は海外発送費を加算する。
  • フルート教室検索を申し込んでいる場合は年間維持費を加算する。
  • 料金の基準値は「年間固定費」テーブルに置く。年度keyのレコード内に今年度分・次年度分が併存している。将来の整理構想はあるが、今回全面的に再設計する指示はない。

3.2 途中入会と翌年への充当

  • 入会時に請求する入会金と1年分の年会費は、入会する月によって減額しない。
  • ユーザーが示した入会月の丸め：14日までなら当月1日、15日以降なら翌月1日。
  • 入会時の年会費は、当該年の対象月分と翌年への充当分として扱う。入会金そのものとは分ける。
  • 初年度の次年度請求では、次年度の年会費から、既に翌年分として充当されている金額を差し引く。
  • 次年度の追加納入がなくても、既入金によって資格がある期間は会報を発送する。期限後は資格停止として管理する。
  • 入会年1月1日時点で22歳、翌年1月1日時点で23歳となる場合、翌年に充当した金額を通常年会費の月額に換算して扱う、という説明があった。具体的な端数月・期限日の処理は未確認。
  • 丸める元の日付を「初回入金日」とするかは、明示的な最終確認が未了。紹介制度では「入金＝入会」と確認されたが、すべての入会処理への適用は別途確認する。

3.3 紹介者制度の割引

  • 2027年分から適用する方針。
  • 対象は正会員本人の年会費だけ。家族会員費、会報オプション、海外発送費、教室維持費は対象外。
  • 対象となる紹介1人につき年会費の12分の1を免除する。最大12人分で本人年会費は0円、マイナスにはしない。
  • 13人目以降も紹介制度は利用できる。年会費割引以外のインセンティブがあるとの説明だが、具体的な内容は本会話で定義されていない。紹介受付そのものを12人で止めない。
  • 紹介実績の集計期間は10月1日〜翌9月30日。これは紹介人数の実績計算だけの期間であり、年会費の1月〜12月とは区別する。
  • 対応例：2026年10月に発行する2027年分の請求には、2025年10月1日〜2026年9月30日の実績を対応させる。制度開始前の期間を含む初年度の扱いは未確認。
  • 紹介の成立は入金による入会確定時点。ユーザーは、この時点で紹介コードの 利用状態 を 「発行済み」 に変更すると説明した。この名称を「利用済み」などへ勝手に置き換えない。
  • 割引辞退者は割引しない。辞退意思を年度ごとに聞き直す方向だが、単位・保存方法・確定時期は未決。
  • 22歳以下の紹介者について割引単価をその人の適用基本年会費の12分の1とする具体式、端数金額の処理は、実装前に最終確認する。

3.4 既入金・繰越金と紹介割引の併用【検討中】

繰越・次年度充当には途中入会分だけでなく、返金相当額や過入金を次年度入金として扱う場合もある。

ユーザーが示した検討順序は「次年度本人年会費から紹介割引を引き、さらに対象年度への既入金・繰越金を引いた額を請求する」。12人紹介して本人年会費が0円になった場合など、充当しきれない既入金をさらに翌年度へ繰り越すことも検討する。

これは決定事項ではない。 事務局で検討予定。超過分を消す、返金する、翌年へ移す、家族会員費・オプションへ充当するといった処理を独断で実装しない。紹介割引による年会費の下限0円と、預かり金の残額の扱いは別問題である。

5. 現行の請求処理

5.1 呼び出し元と親スクリプト

「会員情報_202108」の「請求書作成」ボタン2か所から、対象請求書作成2026（ID 248）を実行する。

  1. 元のレイアウト番号を保存し、「会員情報_202108」へ移動。
  2. gNYearを請求年度として取得し、請求書発行日を入力する。
  3. 発行日の年がgTodayの年〜その翌年に入るか確認し、「請求」か「督促」を選択。
  4. 現在の対象レコードを先頭から順に処理。対象会員の検索・除外判定はこのスクリプト内では行わない。
  5. 会員番号、請求年、請求コード、請求手段、請求／督促、請求日をJSONで子スクリプトに渡す。
  6. 子の結果が000なら会員の請求書発行日を更新し成功数を加算、001なら重複スキップ、それ以外はエラー数を加算。
  7. 元のレイアウトへ戻る。集計件数の画面表示・結果返却はない。

5.2 子スクリプト

請求書作成2026（ID 251）は以下を実行する。

  • 「会員番号＋請求書作成日」で重複検索。請求年度、請求／督促、請求手段は重複検索の条件に含まれない。
  • 未作成なら請求書レコードを作成する。
  • 請求年・請求手段・請求／督促で 請求書Msg2026（元テーブル：Org_Message）の文面を参照する。
  • 請求コードで 年会費詳細2026（元テーブル：年会費請求詳細）を参照し、請求文・決済URLを取得する。
  • 氏名、会員番号、年度、月、請求内訳、決済URL、氏名カナを文面に差し込む。
  • 郵送・口座振替Yは郵送本文を保存する。
  • メール・口座振替Mはメール本文・件名を保存し、その場でSMTP送信する。メール先は有効なメール履歴を変更日降順で参照する。
  • 送信直後のエラー判定がなく、送信済を設定する。メールアドレスの有無は履歴用の区分に使うが、送信を止める条件にはしていない。
  • 会員履歴登録（ID 136）を呼び、請求手段・請求／督促・メールアドレス有無を記録する。
  • 重複なら001、それ以外の通常経路は000を返す。作成・送信・履歴登録の成功を個別に検証した成功コードではない。

通常請求から口座振替会員を除く条件や、振込会員の郵送督促を除く条件は、この親子スクリプトにはない。現状は実行前の対象選択に依存している。
