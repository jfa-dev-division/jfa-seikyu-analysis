# 年間固定費：年度と参照フィールドの不整合

作成日：2026年10月14日。参照資料：2026年10月13日9:45作成の `DDL20261008/JFA_Data_fmp12.xml`。

この資料はDDR上の参照定義の指摘であり、修正済み報告ではない。料金レコードの実値は未確認のため、実際に金額差や過去の誤請求が生じたとは断定しない。

## 1. 「箇所」の表現と正確な名称

会話の最初の表に書いた「会員側の会報オプション」「請求内訳側の教室維持費」「請求本文に表示する基本年会費」は役割の説明であり、正確なフィールド名ではなかった。本書では計算式を持つ元テーブル・フィールドと、式中の参照先TO・フィールドを分けて記載する。

- `元テーブル::計算フィールド`：編集を検討する計算定義の所在地。
- `参照TO::フィールド`：その計算式から参照する項目。
- `年間固定費`と`本年度固定費`は別のTOだが、元のテーブルはいずれも「年間固定費」。
- 年間固定費は年度keyごとに今年度分・次年度分の料金を持つ。ユーザーは将来の整理を考えているが、今回は現行構造のまま矛盾を特定する段階。

## 2. 年間固定費を参照するTO

| TO名 | 接続条件 | リレーションID |
| --- | --- | --- |
| 年間固定費 | Association_members_201905::gYear＝年間固定費::年度key | 134 |
| 本年度固定費 | 年会費請求詳細::年度＝本年度固定費::年度key | 202 |
| Fix_Coast_Y | Payment_History::年度＝Fix_Coast_Y::年度key | 191 |
| 年間固定費_指定年度 | Association_members_201905::gSyear＝年間固定費_指定年度::年度key | 206 |

例として `gYear＝2026`、`gNYear＝2027`、`年会費請求詳細::年度＝2027` とする。

- `年間固定費`は年度key＝2026のレコードを選ぶ。その「次年度」欄が2027年分。
- `本年度固定費`は年度key＝2027のレコードを選ぶ。その「今年度」欄が2027年分で、「次年度」欄は2028年分。
- 2027年料金を得るための2つの経路は、2026年レコードの次年度欄と2027年レコードの今年度欄。この実値の一致は別途確認が必要。
- `年会費詳細2026`は「年会費請求詳細」の別TO。関連先の計算フィールドは、DDRで `Calculation table="年会費請求詳細"` と定義されている。請求書側に同名の固定費TOが直接つながっていないことだけを根拠に参照不能とは判断しない。

## 3. 会話で指摘した4つの計算フィールド

### A. Association_members_201905::会報送付opt

- フィールドID：215。XML行番号：3927。
- 現行の参照：`年間固定費::今年度会報購読opt費`。
- 事務局長・事務局次長は0円。それ以外で紙媒体とPDFを両方受け取る場合に今年度料金を返す。
- `Association_members_201905::次年度請求額_New`（ID 181、行3116）が、この結果を次年度の請求合計へ加算している。
- 2026年に2027年分を請求する例では、ここだけ2026年の会報オプション料金を加える。
- 修正の方向【未実施】：次年度請求側で次年度のオプション料金を使う。会報送付opt自体は今年度用途もあるため、単純に「今年度」を「次年度」へ置換しない。既存の役職免除の扱いも確認する。

### B. 年会費請求詳細::教室維持費

- フィールドID：37。XML行番号：22101。
- 現行式：`教室フラグ * 本年度固定費::次年度教室年間維持費`。
- 請求対象年度＝2027なら、本年度固定費は年度key＝2027を選ぶ。その次年度料金は2028年分になる。
- 請求金額合計は `年会費額 + オプション費用合計` で、オプション費用合計にはこの教室維持費が含まれる。文面だけでなく請求内訳の合計額に影響する参照である。
- 修正の方向【未実施】：現在の年度接続を維持するなら `本年度固定費::今年度教室年間維持費` を使う形が整合する。

### C. 年会費請求詳細::r教室文

- フィールドID：28。XML行番号：22024。
- 現行式は、教室維持費の説明文字列に `本年度固定費::次年度教室年間維持費` を連結している。
- Bと同じく、請求対象年度の翌年料金を表示する。
- 修正の方向【未実施】：Bの金額計算と同じ対象年度の料金にそろえる。計算額だけを直して文面を残さない。

### D. 年会費請求詳細::オプション文

- フィールドID：42。XML行番号：21872。
- 22歳以下の基本年会費表示には `本年度固定費::次年度学割年会費`、それ以外には `本年度固定費::次年度年会費` を使う。
- 請求対象年度＝2027なら、表示される基本料金は2028年分になる。
- 一方、本人分の実際の請求額表示には、別に `年会費請求詳細::年会費額` を使う。この値は請求パターン更新時に `Association_members_201905::次年度請求分_New` から渡される。
- したがって「基本料金の表示がずれる」ことと「本人分の請求額がずれる」ことは区別する。表示の指摘だけで本人分請求額の誤りを断定しない。
- 修正の方向【未実施】：対象年度の今年度学割年会費／今年度年会費を表示する。

## 5. 別枠の追加確認事項

以下は上記4フィールドの指摘と分ける。現役の用途や影響範囲を確認するまで、修正対象に自動追加しない。

- `Association_members_201905::請求opt_No`（ID 252、行4619）は、会報オプションの適用フラグに`会報送付opt > 0`、海外発送の適用フラグに今年度料金を返す`海外会報発送費 > 0`を使う。次年度から料金の有無が変わる場合、請求パターンのフラグと次年度料金が一致するか確認する。
- `Association_members_201905::指定年度基本年会費`（ID 270、行5495）は22歳以下の分岐で `年間固定費_指定年度::今年度学割月額年会費`、通常の分岐で `今年度年会費`を参照している。月額／年額の単位が異なる。次年度請求の主経路とは別なので、使用箇所を追ってから判断する。
- 旧式には `General_Ref_Data::協会会費` や固定値500を使う計算も残る。残存定義だけを根拠に現在の請求に影響すると決めつけず、現役経路を確認する。

## 6. 修正前後の確認方法

1. 年間固定費の対象年レコードが存在し、年度keyが重複していないことを実データで確認する。
2. 前年レコードの次年度欄と対象年レコードの今年度欄が同じ金額になっているか照合する。
3. 今年・次年・翌々年で料金を意図的に変えたテストデータを使い、年度ずれが金額として見える状態にする。
4. 会員画面の次年度合計、請求内訳の合計、メール本文、郵送本文を照合する。
5. 今年度計算と既存免除ルールが変わらないことを確認する。既存の請求本文は保存済み文字列、関連計算表示は再計算され得る点も区別する。
6. 変更はFileMaker本体の定義へ行う。DDR XML自体を書き換えることを修正完了とはしない。修正後のDDRで定義を再確認する。
