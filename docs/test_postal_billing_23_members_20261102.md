## 実際に行った流れ

### 1. コピーと対象者を確認

1. 起動中のMac版FileMakerで対象ファイルの実パスを確認した。Parallelsは起動していない。
2. 会員データの「状態＝正会員」「請求手段＝郵送」を照合し、21名と確認した。
3. 紹介割引3名を確認用に加えること、口座振替Yは含めないことをユーザーと確認した。
4. 年会費納入済みの検証会員Xについて確認し、ユーザーの指示で除外した。最終対象23名は全員、本人年会費の請求残額が正の値。

人が画面で対象を確認する場合は、会員レイアウトの検索モードで「状態＝正会員」「請求手段＝郵送」を同じ検索条件に入力する。年会費納入済みの検証会員Xを除外し、紹介割引3名は会員番号で別途確認する。検索条件を追加する場合、各条件にも「状態＝正会員」を指定する。

### 2. 先の3名分をリセット

ユーザーに確認したうえで、今回の開発で作成した以下だけを主キーで特定して削除した。

- 検証会員J・検証会員N・検証会員Qの2027年分、2026-11-02作成の検証請求書：3件。
- その請求書作成時に自動登録された同日「請求（郵便）」の会員履歴：3件。

「6件」は6名分ではなく、3名×請求書と履歴の2種類。テスト前からの請求書や入金履歴は削除していない。比較用検証会員Yも削除していない。旧履歴3件が残っていないことを作成後に再確認した。

人が行う場合も、請求書と会員履歴を別々に検索し、会員番号だけで削除せず、年度・作成日・事由・作成時刻まで確認して当該レコードだけを削除する。この削除は実施済みなので、再度行わない。

### 3. 2027年用の請求パターンをそろえ、請求書を作成

実際にはコピー専用の補助スクリプト `検証_2027郵送23名作成（コピー専用）` を作成し、実行した。以下の処理を23名について順に行った。

1. `会員情報_202108` で会員番号を完全一致検索し、1件だけであること、`gNYear＝2027` を確認。
2. 会員の `次年度請求分_New`、`請求opt_No`、`次年度紹介割引`、`次年度請求額_New` を取得。
3. 既存の `新請求パターン更新` を実行。2027年・割引後の本人年会費・オプションに合うパターンを生成または再利用し、会員の `請求ptrコード` を更新。
4. パターンの `請求金額合計` と会員の `次年度請求額_New` が一致することを確認。
5. 修正済みの `請求書作成2026` に、会員番号、請求年2027、取得した請求コード、手段「郵送」、種別「請求」、日付2026-11-02、紹介割引額を渡して実行。
6. 子スクリプトの成功結果を確認し、会員の `請求書発行日` を2026-11-02に設定して確定。
7. 最後に今回の23名・2027年・同日作成の請求書だけを検索し、`請求書印刷A4` に表示。

紹介割引3名は登録上の請求手段が「口座振替」のため、**検証の呼び出し引数だけ「郵送」**とした。会員の登録上の請求手段は変更していない。紹介割引は既存の本人年会費計算ですでに差し引かれており、合計から再度引いていない。

既存の親 `対象請求書作成2026` は今回は実行していない。今回の実操作は補助スクリプトから、既存の更新処理と子スクリプトを会員ごとに呼び出したもの。`新請求パターン全更新` も実行していない（正会員全体を対象にするため）。

処理結果は「作成成功：23件」。請求書テーブルの総件数はリセット後4,442件から4,465件となった。既存の比較用検証会員Yを含めると2027年請求書は24件だが、現在のA4確認対象は23件。

### 4. 金額と本文を確認

| --- | ---: | ---: | --- |
| 通常の本人年会費 | 17 | 8,400円 | 紹介割引の明細・説明なし |

紹介割引の明細と「会員紹介制度の割引を適用しました」の説明は対象3名だけに存在した。`###`、`{{紹介割引明細}}`、`DDDD` の未置換はなかった。今回は最終テンプレートから新規作成した本文を確認しており、生成後の本文への追加修正は行っていない。

使用した2027年パターン：S00040（7,700円・opt0）、S00041（8,400円・opt0）、S00042（8,400円・opt1）、S00043（3,500円・opt4）、S00044（8,400円・opt8）。今回新たに生成されたのはS00042～S00044。これらのコードを本番へ固定コピーしない。

### 5. A4を確認し、その画面を残す

1. `請求書印刷A4` の「プレビュー」を開いた。
2. 通常分、紹介割引3名全員、22歳以下、家族会員費あり、教室維持費ありを目視確認した。
3. 各ケースで振込先、会員番号・カナ、最終行の振込注意書きまで一枚に表示され、住所変更QRと重ならないことを確認。
4. 最終ページへ移動して合計23ページと確認し、先頭ページへ戻した。

現在はこの23件のプレビューを残している。左上のページ番号または左右矢印で確認できる。今回の並びでは、紹介割引は3・17・21ページ、家族会員費ありは4ページ、22歳以下は8ページ、教室維持費ありは13ページ。

決済URLは別担当者が作成するため空欄のまま。今回はこの状態での確認結果であり、URL追加後の印刷状態は未確認。

## 後から同じ23件を表示する手順

作成スクリプトを再実行せず、請求書を検索して表示する。

1. プレビューを終了し、レイアウトを `請求書2026` にする。
2. 検索モードで「請求年＝2027」「請求書作成日＝2026/11/2」「請求手段＝郵送」を同じ検索条件に設定し、検索する。
3. この時点のコピーでは比較用検証会員Yを含む24件が該当する。検証会員Yのレコードへ移動し、「レコードを対象外に」して23件にする。**削除ではない。**
4. `請求書印刷A4` に切り替え、「プレビュー」を開く。

今後同日作成の別レコードが増えた場合は、次の会員番号一覧とも照合する。
